# 电商多平台经营分析指标字典

> 适用项目：淘宝 / 京东 / 抖音 三平台电商存量经营分析
> 数据范围：9 张业务表（`data/` 目录），统计窗口 2025-01-01 ~ 2026-12-28，统计快照日 **2026-12-31**
> 口径总则：除漏斗指标取自 `user_behavior` 外，交易类指标**仅统计 `order_status = '已完成'` 的有效订单**；金额一律使用 `total_amount`（订单实付总额）/ `item_total`（明细行小计），单位元；去重口径在每个指标内显式注明。
> **两套「下单」口径不可互换**：漏斗的「下单」来自行为日志 `user_behavior`（事件口径），GMV/购买用户的「下单」来自交易表 `order`（订单口径），两者用户集合的差异已量化，见指标 27（`output/metrics/behavior_order_overlap.csv`）。
> PII 说明：`user.csv` 的 `phone` / `email` / `platform_user_id` 为 PII 形态字段（非真实个人信息），**不纳入任何指标、分析与产出**。

---

## 一、口径约定（全局）

| 约定项 | 说明 |
|---|---|
| 有效订单 | `order_status = '已完成'` 的订单。待付款、已付款、已发货、已取消均不计入 GMV 与有效订单量 |
| 有效购买用户 | 至少有 1 笔有效订单的去重用户（`COUNT(DISTINCT global_user_id)`） |
| GMV 金额口径 | 有效订单 `total_amount` 之和。数据中 `total_amount` 恒等于该单全部 `item_total` 之和（10996/10996 完全勾稽），`discount_amount / shipping_fee / tax_amount` 为独立展示字段，未从 `total_amount` 中扣减 |
| 平台口径 | 业务表存平台编码 `taobao / jd / douyin`，经 `platform` 字典映射为淘宝 / 京东 / 抖音；字典中 `pinduoduo`、`tiktok_shop` 无业务数据，不参与统计 |
| 名称关联口径 | 订单表 `order_status / payment_method / shipping_method` 存字典中文名，按字典 `name` 关联；`shipping_method` 中 local、same_city 两个编码同名「同城配送」，关联前按 name 去重（MIN(code)），防止金额翻倍 |
| 时间口径 | 订单时间取 `order_time`，行为时间取 `behavior_time`，注册时间取 `registration_date`；月度按自然月 `strftime('%Y-%m')` |
| 去重粒度 | 用户以 `global_user_id` 去重，订单以 `order_id` 去重，SKU 以 `global_product_id` 去重 |
| 快照日 | R 指标与 Cohort 窗口完整性判断的基准日：2026-12-31（数据最晚业务时间 2026-12-28） |

## 二、交易核心指标

### 1. GMV（有效成交总额）

| 项目 | 内容 |
|---|---|
| 业务定义 | 统计期内已完成订单的实付总金额，衡量平台整体交易盘子 |
| 计算公式 | `GMV = SUM(order.total_amount)`，过滤 `order_status = '已完成'` |
| 统计过滤条件 | 订单状态=已完成；分平台时按 `platform` 分组；分品类时取订单明细 `SUM(item_total)` |
| 口径说明 | 全网 5,692,092.13 元（淘宝 2,322,985.63 / 抖音 1,752,679.64 / 京东 1,616,426.86）。品类 GMV 由订单明细汇总，与订单 GMV 全额勾稽（差异 0 元）。不含取消/待付款订单 |

### 2. 有效订单量

| 项目 | 内容 |
|---|---|
| 业务定义 | 统计期内状态为「已完成」的订单笔数 |
| 计算公式 | `有效订单量 = COUNT(DISTINCT order_id)`，过滤 `order_status='已完成'` |
| 统计过滤条件 | 同上；分会员等级 / 品类 / 平台时按相应维度分组 |
| 口径说明 | 全网 2,216 笔（总下单 10,996 笔，完成率 20.15%）。注意：本数据订单状态为随机分布，完成率不代表真实经营水平 |

### 3. 下单用户数 / 有效购买用户数

| 项目 | 内容 |
|---|---|
| 业务定义 | 下单用户数=有任意状态订单的去重用户；有效购买用户数=有已完成订单的去重用户 |
| 计算公式 | `COUNT(DISTINCT global_user_id)` |
| 统计过滤条件 | 下单用户不过滤状态（4,215 人）；有效购买用户过滤已完成（1,643 人） |
| 口径说明 | 注册用户 5,486 人，其中 1,271 人（23.17%）全窗口无任何订单；有效购买覆盖率 29.95% |

### 4. 客单价（AOV）

| 项目 | 内容 |
|---|---|
| 业务定义 | 每笔有效订单的平均实付金额，衡量单次消费深度 |
| 计算公式 | `客单价 = GMV / 有效订单量` |
| 统计过滤条件 | 已完成订单；分母为订单笔数而非用户数（用户人均消费另算） |
| 口径说明 | 全网 2,568.63 元；抖音 2,604.28 > 京东 2,561.69 > 淘宝 2,547.13，平台间差距 ≤ 2.3%，客单价不是平台 GMV 差距的主因，订单量才是 |

### 5. 有效购买转化率

| 项目 | 内容 |
|---|---|
| 业务定义 | 注册用户中最终产生有效订单的比例，用于城市/年龄/等级/平台等注册用户维度的对比 |
| 计算公式 | `有效购买转化率 = 有效购买用户数 / 注册用户数 × 100%` |
| 统计过滤条件 | 分子为该维度下有已完成订单的去重用户，分母为该维度注册去重用户 |
| 口径说明 | 与「漏斗浏览→下单转化率」不同：分母是注册用户而非浏览用户，引用时须注明 |

## 三、转化漏斗指标（取自 user_behavior 行为日志）

> 漏斗按**各环节去重用户数**构建（同一用户在同一环节多次行为只计 1 人），环节为：浏览 → 加购 → 下单 → 支付。
> 行为日志为独立采样数据，各环节用户集合非严格包含（如 628 人有加购无浏览记录），故本项目采用「环节去重人数」口径而非严格路径口径，已在报告中披露。
> 敏感性对照（报告附录 B，结果文件 `output/metrics/funnel_strict_path.csv`）：严格路径口径要求加购⊂浏览、下单⊂加购、支付⊂下单（用户×平台嵌套集合），全网浏览→支付为 24.86%、淘宝/京东/抖音 28.40%/23.72%/22.95%；该口径受日志采样失真影响仅作对照，主指标一律采用环节去重口径。

### 6. 环节用户数

| 项目 | 内容 |
|---|---|
| 业务定义 | 在某环节发生过对应行为的去重用户数 |
| 计算公式 | `COUNT(DISTINCT global_user_id)`，过滤 `behavior_type = 对应环节` |
| 统计过滤条件 | 浏览/加购/下单/支付四类；分平台时按平台分组 |
| 口径说明 | 全网：浏览 2,711 / 加购 2,368 / 下单 1,953 / 支付 1,734（行为事件口径，与指标 3 的 1,643 名有效购买用户不是同一口径，见指标 27） |

### 7. 环节转化率（相邻环节转化率）

| 项目 | 内容 |
|---|---|
| 业务定义 | 当前环节用户数相对上一环节用户数的比例，定位漏斗具体流失卡点 |
| 计算公式 | `环节转化率 = 本环节去重用户数 / 上一环节去重用户数 × 100%`（SQL：`LAG() OVER (ORDER BY 环节序号)`） |
| 统计过滤条件 | 浏览→加购、加购→下单、下单→支付三段；首环节无前置环节，不计算 |
| 口径说明 | 全网三段为 87.35% / 82.47% / 88.79%，**最大卡点为加购→下单**；抖音同环节仅 72.98%，为全平台最低卡点。本率的分母是行为口径去重用户，不等价于交易口径的购买转化率 |

### 8. 累计转化率（全链路转化率）

| 项目 | 内容 |
|---|---|
| 业务定义 | 某环节用户数占首环节（浏览）用户数的比例，衡量端到端转化效率 |
| 计算公式 | `累计转化率 = 本环节去重用户数 / 浏览去重用户数 × 100%` |
| 统计过滤条件 | 同漏斗口径 |
| 口径说明 | 全网浏览→支付 63.96%；京东 83.15% > 淘宝 63.67% > 抖音 51.51%。该指标衡量行为链路效率，不代表成交金额或购买用户占比 |

### 9. 品类浏览→下单转化率

| 项目 | 内容 |
|---|---|
| 业务定义 | 在某品类商品发生浏览的用户中，在同品类发生下单行为的用户占比 |
| 计算公式 | `COUNT(DISTINCT 下单用户) / COUNT(DISTINCT 浏览用户) × 100%`（用户与品类同时匹配） |
| 统计过滤条件 | 行为表关联商品表取 `category`；仅取浏览、下单两类行为 |
| 口径说明 | 最高运动户外 30.04%，最低服装鞋帽 20.94%；反映品类间「逛了不买」程度差异 |

## 四、用户生命周期指标

### 10. R — 最近消费间隔（Recency）

| 项目 | 内容 |
|---|---|
| 业务定义 | 用户最近一笔有效订单距统计快照日的天数 |
| 计算公式 | `R = CAST(julianday('2026-12-31') - julianday(MAX(order_time)) AS INT)`，过滤已完成订单 |
| 统计过滤条件 | 仅对有有效订单的 1,643 名用户计算 |
| 口径说明 | R 越小价值越高；打分用 `NTILE(4) OVER (ORDER BY R DESC)`，最近消费的 25% 用户得 4 分 |

### 11. F — 消费频次（Frequency）

| 项目 | 内容 |
|---|---|
| 业务定义 | 用户在统计窗口内的有效订单笔数 |
| 计算公式 | `F = COUNT(DISTINCT order_id)`，过滤已完成订单 |
| 统计过滤条件 | 同 R |
| 口径说明 | 数据中每用户 F 集中在 1~20；`NTILE(4)` 按 F 升序分桶，高频用户得 4 分；F=1 的用户在部分分层中不参与订单间隔计算 |

### 12. M — 累计消费金额（Monetary）

| 项目 | 内容 |
|---|---|
| 业务定义 | 用户在统计窗口内有效订单实付金额累计 |
| 计算公式 | `M = SUM(total_amount)`，过滤已完成订单 |
| 统计过滤条件 | 同 R |
| 口径说明 | `NTILE(4)` 按 M 升序分桶，高额用户得 4 分；并列时以 F、global_user_id 兜底排序保证可复现 |

### 13. RFM 四类分层

| 项目 | 内容 |
|---|---|
| 业务定义 | 基于 R/F/M 三个 1~4 分，按固定规则把有效消费用户划入四类，规则互斥且穷尽 |
| 计算公式（分层规则） | ① **高价值用户**：R≥3 且 F≥3 且 M≥3；② **流失预警用户**：R≤2 且（F≥3 或 M≥3）；③ **潜力用户**：R≥3 且不满足高价值；④ **低价值用户**：其余（R≤2 且 F、M 均低） |
| 统计过滤条件 | 仅 1,643 名有效消费用户；3,843 名无有效订单用户不打分，作为「无有效消费人群」单独披露 |
| 口径说明 | 高价值 434 人（26.42%）贡献 46.48% GMV；流失预警 380 人（23.13%）贡献 30.01%；潜力 387 人（23.55%）贡献 11.28%；低价值 442 人（26.90%）贡献 12.23%。阈值为本项目口径，真实业务应结合复购周期调参 |

### 14. Cohort 30 / 60 / 90 天留存率

| 项目 | 内容 |
|---|---|
| 业务定义 | 以用户注册月份为首购批次（Cohort），注册后 N 天内再次产生已完成订单的用户占该批次人数比例 |
| 计算公式 | `留存率(N) = 注册后第 1~N 天内有有效订单的用户数 / 批次注册用户数 × 100%`（N=30/60/90，累计窗口；SQL：`julianday(order_time)-julianday(reg_date) BETWEEN 1 AND N`） |
| 统计过滤条件 | 以 `user.registration_date` 所在月分批；只统计已完成订单；注册当日订单不计入留存（offset 从 1 起） |
| 口径说明 | 窗口完整批次（90 天窗口完整的 21 批）的平均留存：30 天 1.78%、60 天 3.22%、90 天 4.66%。2026-10 起批次的 60/90 天窗口在快照日前未走完（`complete_60d/90d=0`），矩阵中保留数值但标注为未完结窗口。另：50.01% 订单时间早于注册日期（时序异常），负 offset 一律不计入任何留存窗口。**敏感性对照**：宽松口径（注册前/当日订单全部计入，offset ≤ N，同 21 批）为 30 天 15.29%、60 天 16.49%、90 天 17.70%（`output/metrics/cohort_sensitivity.csv`，报告附录 A），结论方向不变，主指标仍取严格口径 |

### 15. 平均订单间隔

| 项目 | 内容 |
|---|---|
| 业务定义 | 同一用户相邻两笔有效订单的平均间隔天数，衡量复购节奏 |
| 计算公式 | 用户内按 `order_time` 排序，`AVG(相邻订单天数差)`，再按 RFM 分层取均值（SQL 排序 + pandas diff） |
| 统计过滤条件 | 仅 F≥2 的用户有间隔值；F=1 用户该指标为空，报告中记「无复购」 |
| 口径说明 | 流失预警 135.7 天、潜力 268.5 天、高价值 254.0 天 |

## 五、商品与结构指标

### 16. 头部 20% 用户 GMV 集中度（帕累托）

| 项目 | 内容 |
|---|---|
| 业务定义 | 累计有效消费金额最高的 20% 用户所贡献的 GMV 比例，衡量用户集中度 |
| 计算公式 | 按 M 降序 `NTILE(5)`，第 1 组（头部 20%，329 人）`SUM(M) / 全量 M × 100%` |
| 统计过滤条件 | 有效消费用户 1,643 人 |
| 口径说明 | **43.40%**，低于经典 80/20，用户消费贡献较分散 |

### 17. 头部 20% SKU GMV 集中度（帕累托）

| 项目 | 内容 |
|---|---|
| 业务定义 | 有效销售额最高的 20% 动销 SKU 贡献的 GMV 比例 |
| 计算公式 | 按 SKU 有效销售额降序 `NTILE(5)`，第 1 组（409 个 SKU）销售额 / 全部有效销售额 |
| 统计过滤条件 | 仅动销 SKU（2,043 个）参与分桶 |
| 口径说明 | **47.63%**，爆品集中度中等 |

### 18. 爆品 SKU

| 项目 | 内容 |
|---|---|
| 业务定义 | 观察窗口内有效销售额排名位于动销 SKU 前 20%、且库存状态为「有货」的 SKU |
| 计算公式 | 动销 SKU 内 `NTILE(5) OVER (ORDER BY sales_gmv DESC)=1 AND stock_status='有货'` |
| 统计过滤条件 | 销售额取已完成订单明细；本数据全部 SKU `stock_status` 均为有货 |
| 口径说明 | 409 个（占全部 SKU 12.40%），贡献 47.63% GMV（271.11 万元） |

### 19. 滞销 SKU

| 项目 | 内容 |
|---|---|
| 业务定义 | 观察窗口内无任何有效成交（已完成订单）的 SKU |
| 计算公式 | `SUM(CASE WHEN 已完成 THEN item_total END) = 0 或 IS NULL` |
| 统计过滤条件 | 商品表全量 3,298 个 SKU 左连接有效销售 |
| 口径说明 | 1,255 个（38.05%）零有效成交，其中 **358 个全窗口从未被下单**、897 个仅出现在非完成状态订单中。因库存字段只有「有货」无库存量，本指标以动销速度代理滞销，库存深度结论受限（见项目局限性） |

### 20. 月度 GMV

| 项目 | 内容 |
|---|---|
| 业务定义 | 按月汇总的有效 GMV / 有效订单量 / 购买用户数 / 客单价，用于趋势分析 |
| 计算公式 | `GROUP BY strftime('%Y-%m', order_time)` |
| 统计过滤条件 | 已完成订单，2025-01 ~ 2026-12 共 24 个月 |
| 口径说明 | 峰值 2026-10（27.79 万元），谷值 2026-02（17.93 万元）；2025 全年 276.35 万元，2026 全年 292.86 万元，同比 +5.97% |

## 六、用户价值补充指标

### 21. LTV（购买用户人均累计消费）/ ARPU（注册用户人均 GMV）

| 项目 | 内容 |
|---|---|
| 业务定义 | 单位用户在统计窗口内贡献的平均有效 GMV，按分母不同分为两种口径，引用时必须注明分母：LTV 衡量已购用户的单客价值深度，ARPU 衡量全部注册流量（含未转化用户）的平均变现 |
| 计算公式 | `LTV = 有效GMV / 有效购买用户数 = SUM(M) / 1,643 = 3,464.45 元/人`；`ARPU = 有效GMV / 注册用户数 = SUM(M) / 5,486 = 1,037.57 元/注册用户`；分层 LTV = 该层 M 均值（高价值 6,096.37 / 流失预警 4,495.03 / 潜力 1,658.50 / 低价值 1,575.38） |
| 统计过滤条件 | 已完成订单；LTV 分母为有 ≥1 笔有效订单的 1,643 名去重用户；ARPU 分母为全部 5,486 名注册用户（含 3,843 名无有效订单用户，其 M 按 0 计入）；注册月份趋势以 `registration_date` 所在月分批（`output/metrics/ltv_reg_month.csv`） |
| 口径说明 | 两口径相差 3.34 倍，差异即 70.05% 注册用户无有效订单的量化体现；按注册月份注册口径 ARPU 区间 786.78~1,434.59 元、购买用户 LTV 区间 2,859.64~4,367.05 元。M 值定义同指标 12，不重复打分 |

## 七、扩展专题与补充指标（对应报告 1.4 / 2.3 / 2.9 节与附录 C~G）

> 本小节指标 22~26 基于**全部 10,996 个订单**（非"已完成"GMV 口径），为应需求追加的存量专题；金额字段勾稽关系：`total_amount = Σ order_item.item_total`（误差 < 1e-12），`discount_amount/shipping_fee/tax_amount` 不参与勾稽。

### 22. 订单状态结构 / 流失类意向金额

| 项目 | 内容 |
|---|---|
| 业务定义 | 全部订单按 5 种状态的分布，并将状态分为三组：流失类=待付款+已取消、在途类=已付款+已发货、已完成；意向金额=各组 `total_amount` 之和 |
| 计算公式 | 订单占比 = 状态订单数 / 10,996；意向金额 = `SUM(total_amount) GROUP BY order_status` |
| 统计过滤条件 | 全量订单（含非完成）；平台/金额带交叉表分别见 `order_status_platform.csv`、`order_status_amount_band.csv`，品类金额见 `order_status_category.csv` |
| 口径说明 | 待付款 2,224（20.23%）、已取消 2,177（19.80%）、已付款 2,192、已发货 2,187、已完成 2,216（20.15%）；流失类合计 4,401 单（40.02%）、1,114.1 万元。**状态与平台/促销/金额带/用券 4 项卡方均独立（p≥0.145，V<0.03），该 40.02% 不能解读为真实流失率**（详见报告附录 C） |

### 23. 促销完成率 / 折扣深度 / 用券渗透率

| 项目 | 内容 |
|---|---|
| 业务定义 | 按 `promotion_id`（5 类，含"无促销"）与是否有 `coupon_code` 分组的订单占比、完成率与折扣深度；用券渗透率 = coupon_code 非空订单占比 |
| 计算公式 | 完成率 = 该组已完成订单数 / 该组订单数；折扣深度 = `discount_amount /(total_amount + discount_amount)×100%`（自定义口径，两字段不勾稽，仅作组间相对比较） |
| 统计过滤条件 | 全量订单；分平台结果见 `coupon_summary.csv`、`promo_type_summary.csv`（含完成单 GMV），BI 表 `fct_promo_summary.csv` |
| 口径说明 | 用券渗透 49.8%（5,476/10,996）；5 类促销完成率 19.04%~21.07%、折扣深度 12.41%~12.71%（"无促销"亦有 12.71%）；用券/无券完成率 20.14% vs 20.16%（p=0.997），折扣深度×完成 rho=0.006（p=0.55）。**无促销效果信号，不做因果解读**（附录 D） |

### 25. UPT / 件单价 / 跨品类订单占比

| 项目 | 内容 |
|---|---|
| 业务定义 | UPT（Units Per Transaction）= 每单件数；件单价 = 每件商品平均成交额；跨品类订单占比 = 含 ≥2 个一级品类的订单比例 |
| 计算公式 | `UPT = SUM(quantity) / 订单数`；`件单价 = SUM(item_total) / SUM(quantity)`；跨品类占比 = 不同品类数 ≥2 的订单 / 订单数 |
| 统计过滤条件 | 同时给全量订单与已完成订单两档口径（分平台），已完成档与 GMV 口径对齐；结果 `basket_metrics.csv` |
| 口径说明 | 本数据 quantity 恒为 1、每单固定 2~3 行，故件数=明细行数，传统"多件订单占比"恒 100% 不采用；已完成口径全网 UPT=2.516、件单价 1,020.82 元，与客单价 2,568.63 元勾稽（UPT×件单价≈AOV）；跨品类占比 93.77%（附录 E.1） |

### 26. 品类共购关联规则（support / confidence / lift）

### 30. 维度同质性检验（卡方 + Cramer's V）

| 项目 | 内容 |
|---|---|
| 业务定义 | 判断某维度（品牌 / 支付方式 / 配送方式 / 性别 / 停留时长 / 商品分层）与订单状态、金额带、平台、是否完成之间是否存在可用于业务的关联 |
| 计算公式 | 卡方统计量 χ² + 效应量 Cramer's V = √(χ² / (n × min(r-1, c-1)))；判定：V<0.05 无可用信息、0.05≤V<0.1 弱关联、V≥0.1 有信息 |
| 统计过滤条件 | 订单级维度取全量订单（10,996）；商品级维度取订单明细行（27,523）；停留时长取行为事件（21,998；四环节子集 14,730） |
| 口径说明 | 24 项检验中 18 项 V<0.05；brand×平台 0.057、brand×一级品类 0.0723 为弱关联；`gender × 平台` p=0.0065 显著但 V=0.0303（说明大样本下显著性 ≠ 业务意义）；`sku_label` 相关检验 V=0.0245~0.179 属**口径内生**（该标签由已完成订单销售额定义），不构成业务发现。落盘 `dim_homogeneity_check.csv`（报告附录 G） |

### 31. 帕累托累计贡献曲线（CUME_DIST）

| 项目 | 内容 |
|---|---|
| 业务定义 | 按价值降序排列后，头部累计人数（SKU 数）占比对应的累计 GMV 占比曲线 |
| 计算公式 | `CUME_DIST() OVER (ORDER BY 价值 DESC, 主键)`；取 10%~100% 十个节点，节点内人数 = `COUNT(cd <= 节点)`，累计贡献 = `SUM(金额) / 总额` |

| 口径说明 | 用户头部 10%/20%/50% 累计贡献 28.57% / **43.32%** / 77.11%；SKU 头部 10%/20%/50% 累计贡献 29.03% / **47.55%** / 80.96%。**与指标 16/17 的 NTILE 头部 20% 定义不同**（用户 328 vs 329 人、SKU 408 vs 409 个，NTILE 把余数分配给前面的桶），43.32% 与 43.40% 是同一数据的两套切分。落盘 `pareto_cumulative.csv`（报告 2.3 节，图 fig17） |
